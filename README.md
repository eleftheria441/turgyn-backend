# Turgyn Backend

Node.js/Express бэкенд для Turgyn: общая база данных для веб-кабинета УК и мобильного приложения жителя, реальная аутентификация (bcrypt + токены), scoped API для резидентов (житель никогда не получает чужие данные).

Заменяет прежнюю схему "всё в localStorage браузера" — теперь директор, бухгалтер, диспетчер и жители могут работать с разных устройств одновременно, видя одни и те же данные.

## Что внутри

```
turgyn-backend/
  server.js            — точка входа, статика + маршруты API
  src/store.js          — хранилище (JSON-файл data/db.json + data/sessions.json)
  src/auth.js            — хэширование паролей (bcrypt), токены, middleware авторизации
  src/seedData.js        — генерация демо-данных при первом запуске (2 ОСИ)
  src/routes/auth.js      — POST /api/auth/login, /logout, GET /api/auth/me — вход сотрудников УК
  src/routes/state.js     — GET/POST /api/state — вся база (только для сотрудников, пароли никогда не отдаются клиенту)
  src/routes/resident.js  — /api/resident/login, /me, /pay, /request — доступ жителя только к своим данным
  public/index.html       — веб-кабинет УК (лендинг + админка + AI-аналитик)
  public/app.html         — мобильное приложение жителя
```

## Как это работает

Веб-кабинет УК и приложение жителя — это те же файлы, что вы уже видели, но теперь они умеют говорить с этим сервером:

- Если сервер доступен — сотрудники входят через `/api/auth/login`, все данные читаются/пишутся через `/api/state`; житель входит по телефону/лицевому счёту через `/api/resident/login` и получает только свои данные.
- Если сервер недоступен (например, кто-то открыл `index.html` двойным кликом без сервера) — оба файла автоматически откатываются в локальный демо-режим на localStorage, как раньше. Это специально оставлено для быстрой демонстрации без установки.

Заявка, поданная жителем через `/app.html`, при работающем сервере сразу видна диспетчеру в `/index.html` — это и есть та самая "реальная связь", которой не хватало в чисто локальной версии.

## Быстрый запуск локально

Требуется Node.js 18 или новее.

```bash
cd turgyn-backend
npm install
cp .env.example .env
npm start
```

Откройте `http://localhost:4000` — веб-кабинет УК, `http://localhost:4000/app.html` — приложение жителя.

При первом запуске автоматически создаётся `data/db.json` с демо-данными (2 ОСИ) и демо-доступами:

- `admin` / `admin` — Директор
- `buh` / `buh` — Бухгалтер
- `disp` / `disp` — Диспетчер

**Обязательно смените эти пароли (или удалите демо-сотрудников) перед реальным использованием** — раздел «Сотрудники УК» в кабинете директора.

## Переменные окружения (.env)

```
PORT=4000                 # порт сервера
CORS_ORIGIN=*             # домен фронтенда, если он на другом домене; * — разрешить всем (не для продакшена)
DATA_DIR=./data           # где хранить db.json и sessions.json
```

## Данные и бэкапы

Вся база — один файл `data/db.json`. Это осознанное упрощение для старта (тот же формат, что раньше жил в localStorage), достаточное для одной УК и нескольких ОСИ. Обязательно:

- Регулярно делайте резервную копию `data/db.json` (простой cron с копированием файла или снапшот тома на хостинге).
- Когда данных станет много (десятки ОСИ, сотни тысяч начислений) — перенесите `src/store.js` на настоящую БД (Postgres/MySQL). Весь доступ к данным в проекте нарочно завёрнут в этот один модуль, чтобы такой переход не требовал переписывать остальной код.

## Варианты деплоя

### 1. Railway / Render (проще всего, без сервера в собственность)
1. Загрузите папку `turgyn-backend` в свой Git-репозиторий (GitHub/GitLab).
2. В Railway/Render создайте новый Web Service из этого репозитория.
3. Build command: `npm install`, Start command: `npm start`.
4. Добавьте переменную окружения `CORS_ORIGIN` = адрес вашего сайта (или оставьте `*` на старте).
5. Подключите постоянный диск (Volume) на путь `/app/data` — иначе `data/db.json` будет стираться при каждом деплое.
6. После деплоя сервис даст вам постоянный URL (например `turgyn.up.railway.app`) — это и есть ваш рабочий адрес.

### 2. Docker (свой VPS, любой облачный провайдер с Docker)
```bash
docker build -t turgyn-backend .
docker run -d -p 4000:4000 -v $(pwd)/data:/app/data --env-file .env --name turgyn turgyn-backend
```
Дальше поставьте перед контейнером Nginx с SSL (Let's Encrypt/certbot) и проксируйте домен на порт 4000.

### 3. Обычный VPS без Docker
```bash
git clone <ваш репозиторий>
cd turgyn-backend
npm install
npm install -g pm2
pm2 start server.js --name turgyn
pm2 save && pm2 startup   # автозапуск после перезагрузки сервера
```
Дальше — Nginx как реверс-прокси на 80/443 с SSL (certbot) → `proxy_pass http://localhost:4000`.

## Безопасность перед реальным использованием

- Смените все демо-пароли.
- Установите `CORS_ORIGIN` в конкретный домен вместо `*`.
- Обязательно работайте через HTTPS (Let's Encrypt бесплатен) — иначе токены и данные жителей идут в открытом виде.
- `data/` не должна быть публично доступна через веб-сервер (в Nginx не отдавайте эту папку как статику).
- Токены сессий сейчас живут в файле `data/sessions.json` без срока истечения — для реального продакшена стоит добавить TTL и очистку старых сессий (небольшая доработка `src/auth.js`).

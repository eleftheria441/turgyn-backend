# Turgyn — сервер

Node.js 20 · Express · PostgreSQL

## Хранение данных

Каждая сущность — в своей таблице (`osi`, `accounts`, `services`, `accruals`, `payments`,
`providers`, `prov_invoices`, `prov_payments`, `requests`, `expenses`). Запись целиком лежит
в `data` (jsonb), ключевые поля — ОСИ, период, лицевой счёт — вынесены в индексируемые колонки.

- `meta.ver` — единый счётчик версий. Каждое изменение получает номер.
- `tombstones` — отметки об удалениях, чтобы коллеги узнавали о них.
- `period_locks`, `lock_events` — закрытые периоды и история открытий/закрытий с причинами.
- `users` — сотрудники, пароли только в виде хэша.
- `settings` — реквизиты УК, пеня, статьи расходов, журнал импорта.
- `audit_log` — журнал действий; удалённые финансовые записи сохраняются в нём целиком.
- `state_snapshots` — полный снимок раз в час при наличии изменений, хранится неделя.

При первом запуске данные из старого формата (`app_state`) переносятся автоматически,
старая таблица переименовывается в `app_state_legacy` и остаётся как резервная копия.

## Синхронизация

Кабинет отправляет только изменённые записи (`POST /api/state/changes`) с номером версии,
которую видел. Если запись после этого изменил другой сотрудник — ответ 409, кабинет
перезагружает данные. Изменения коллег приходят в ответе и при опросе `GET /api/state/since`
раз в 30 секунд.

## Закрытие периода

`POST /api/state/periods/close` — директор или бухгалтер. Начисления, оплаты, расходы и расчёты
с поставщиками закрытого месяца нельзя изменить или удалить (ответ 423). Ошибки исправляются
корректировками в открытом периоде. Открыть период может только директор, с причиной.

## API для директора

- `GET /api/state/audit` — журнал действий
- `GET /api/state/export` — полная резервная копия
- `POST /api/state/replace` — загрузка резервной копии с заменой данных
